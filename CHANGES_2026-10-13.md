# Changes — 13 Oct 2026 (CMPB revision)

## Bug fix (affects all published classification and report results)
- `backend/xray_model.py` mapped model output *i* to `DISEASES[i]` (NIH order), but
  `densenet121-res224-all` emits outputs in torchxrayvision order (`model.pathologies`).
  12 of 14 disease names were attached to the wrong output (e.g. "Cardiomegaly" was the
  Consolidation score, "Emphysema" was the Cardiomegaly score), so the LLM was also given
  wrong disease names and GradCAM was computed for the wrong output. Diseases are now looked
  up by name in `model.pathologies`; a missing disease raises an error.

## Evaluation pipeline (`backend/evaluation_pipeline.py`)
- Command-line options: `--location {gradcam,prior,none}`, `--tag`, `--data-dir`,
  `--output-dir`, `--max-images`, `--seed`, `--no-report`. No more hard-coded user paths.
- Real GradCAM ablation: `prior` switches GradCAM off and uses anatomical prior positions;
  `gradcam` uses GradCAM. In both arms the marker locations are now actually given to the LLM
  (previously the prompt never contained them, so both arms sent identical prompts).
- LLM temperature 0 for evaluation, so differences between arms are not sampling noise.
- AUC computed from the raw, untruncated probability of all 14 diseases (previously
  probabilities ≤ 10% were stored as 0).
- Standard sentence-level BLEU-n (brevity penalty exp(1 − r/c), no fallback from BLEU-2 to
  BLEU-1); verified identical to NLTK `sentence_bleu` on 1,000 random pairs. Tokenisation:
  lower-case alphanumeric tokens for both texts.
- API-error reports are no longer scored; images without reference text are counted and excluded.
  Means are over scored reports only, and that number is reported.
- Precision (PPV) added to the metrics table.
- Per-image CSV now stores the generated report, the reference text, the marker positions and
  whether each was GradCAM or prior; `run_config_*.json` records seed, model output order,
  torchxrayvision version, LLM, temperature and counts.
- Sampling: simple random sample of frontal images, `random_state=42` (the value used for the
  May 2026 runs, so the same 200 images are re-evaluated).

## Report generation (`backend/report.py`)
- `generate_report(findings, include_location=False, temperature=None)`. The web app's
  behaviour is unchanged (defaults). Failed calls now return `"error": True`.

## New
- `analysis/validate_statistics.py` — re-analysis of the May 2026 CSVs (CIs, Wilcoxon,
  corrected label order); results in `analysis/results/`.
- `analysis/statistics.py` — statistics for the new runs (bootstrap + DeLong AUC CIs,
  precision, paired Wilcoxon for the ablation); results in `analysis/results_v2/`.
- `run_evaluation.bat "C:\path\to\iu_xray"` — runs both ablation arms and the statistics.

## Known limitation to report in the paper
The `densenet121-res224-all` weights were trained on data that includes OpenI (the IU X-Ray
collection), so IU X-Ray is not an independent external test set for this model.
